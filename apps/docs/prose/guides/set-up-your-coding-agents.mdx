Hand-written tutorial. Commands match `prose/guides/snippets/ai-tutorial-*.sh`; CI runs the same flow in `verify-ai-agent-tutorial.mjs` against a temp directory.

This guide is **optional**: you can use `@zedtech/zedkit-ui` or the backend packages without installing the AI kit.

## Who this is for

You use Cursor, Claude Code, Codex, or similar tools and want a repo-local copy of skills, subagents, commands, and `AGENTS.md` without maintaining separate trees per vendor.

## Prerequisites

- Node.js 22+ and a git repository (any stack).
- One provider for `init`: `cursor`, `claude`, `codex`, `muse`, or `all` (see `zedkit-ai init --help` in [`packages/ai/src/cli.ts`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/src/cli.ts)).

## Steps

### 1. See what the kit ships

```sh
{{snippet:ai-tutorial-list.sh}}
```

You should see preset names, subagents (for example `explorer`), and commands (for example `review`) printed on stdout — same checks as `packages/ai/tests/unit/cli.test.ts` (`list`).

### 2. Copy the kit into the repo

```sh
{{snippet:ai-tutorial-init.sh}}
```

`init` **never overwrites** existing files; it skips paths that already exist ([`install.ts`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/src/install.ts)). This tutorial uses `--preset full` so every bundled command (for example `audit`) has its skill on disk — `validate` checks that link ([`kit.json`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/kit/kit.json)). For Cursor it adds `.cursor/rules/project.mdc` and copies skills into `.agents/`.

Preview without writing:

```sh
npx zedkit-ai init . --provider cursor --dry-run
```

Stdout ends with `dry run: nothing written` and no new files on disk.

### 3. Validate

```sh
{{snippet:ai-tutorial-validate.sh}}
```

**Expected result:** exit code `0` and a single line on stdout:

```text
ok
```

If skills, commands, or provider copies drift, you get `path: message` lines and a non-zero exit (see `validate` in [`cli.ts`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/src/cli.ts)).

`validate` checks file shape and drift — it does **not** run your coding agent. After init, use your tool’s normal workflow to open the repo; the wired rules and skills are the files `init` created.

### 4. Optional project instructions

Ask your agent to run the bundled `setup-ai` skill (copied under `.agents/skills/`) so `AGENTS.md` reflects this repository. That step is interactive and is not part of CI.

### 5. Hand it a bigger task

When the work spans several steps or review lenses, use `/orchestrate` with the
goal in one line (for example `/orchestrate add auth and document the API`). The
orchestrator agent frames the work, dispatches specialists, and returns one
aggregated report without editing files itself.

## Scenario — repo that already has `AGENTS.md`

You already maintain team rules at the root:

```md
# Team rules

Use our internal style guide.
```

Run the same `init` command. When `AGENTS.md` exists but lacks the kit ladder section, `init` **appends** the ladder instead of replacing your text ([`install.ts`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/src/install.ts)). Run `validate` again; stdout should still be `ok`. CI covers this in `runExistingAgentsTutorial` (`apps/docs/fixtures/ai-agent-tutorial.mjs`).

## What gets installed

After `npx @zedtech/zedkit-ai init` (same command as the [home page](/#ai-setup)), you get a project-owned tree the agent tools read:

```text
AGENTS.md                 # root instructions (template or appended ladder)
CLAUDE.md                 # symlink to AGENTS.md
.agents/
  skills/                 # bundled skills (including setup-ai)
  agents/                 # subagent briefs (including orchestrator.md)
  commands/               # slash-command sources (including orchestrate.md)
  personas.md
.cursor/
  rules/project.mdc       # always-on Cursor rules
  commands/setup-ai.md    # runs the setup-ai skill
  skills/                 # symlink into .agents/skills
.claude/
  commands/setup-ai.md
  skills/                 # symlink into .agents/skills
```

`init` logs every path it creates. It never overwrites an existing file.

## Undo

`init` only adds or appends files. To remove the kit:

1. Delete `.agents/` if you no longer want project-owned skills and commands.
2. Remove provider wiring you do not need (for example `.cursor/`, `.claude/`, or symlinks listed in the init log).
3. Revert changes to `AGENTS.md` with git if you only wanted the ladder append temporarily.

There is no uninstall command; keep a commit before `init` so you can roll back.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `validate` prints problems | Run from the repo root; paths are listed as `relative/path: message`. Fix or restore the file, or re-run `init` on a clean branch. |
| `init` skips files | Expected when paths already exist — remove or rename the conflicting file, or use `--dry-run` to preview. |
| Unknown provider | Use `cursor`, `claude`, `codex`, `muse`, or `all` only (`cli.test.ts` rejects unknown providers). |
| Agent ignores instructions | Out of scope for `validate` — confirm your tool loads `.cursor/rules` or the provider copy `init` created. |

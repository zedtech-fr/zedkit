Hand-written guide. Every claim points at
[`identities.css`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ui/src/identities.css),
[`motion.css`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ui/src/motion.css) or the
[`styles.css`](https://github.com/zedtech-fr/zedkit/blob/main/packages/ui/src/styles.css) entry that imports them.

## What an identity is

An identity is a block of CSS variables selected by `data-identity` on `<html>`. It is a second
axis next to light and dark: the `.dark` class picks the mode, `data-identity` picks the look, and
every identity defines both modes.

Components never read the identity. They use tokens (`bg-card`, `rounded-xl`, `shadow-md`,
`font-sans`, `border`), and the identity decides what each token means. Switching identity
restyles the kit, this documentation site and your own screens without changing a component.

| Identity | `data-identity` | Fonts | Radius | Border | Spacing | Shadow |
| --- | --- | --- | --- | --- | --- | --- |
| Mist | `mist` (default, attribute optional) | System sans | 12px (cards) | 1px | stock | Light, diffuse. |
| Press | `press` | Space Grotesk, Newsreader | 0 | 1px | +12% | No shadows: fine ink rules. |
| Tide | `tide` | Inter, heavy weights | 24px (cards) | 1px | +12% | Large soft glows. |
| Volt | `volt` | Geist | 6px (cards) | 1px | -12% (dense) | Layered, with an inner edge in dark. |
| Maison | `maison` | Cormorant, Jost | 2px (cards) | 1px | +30% (airy) | Almost none, very soft. |
| Glass | `glass` | Space Grotesk, Inter | 20px (cards) | 1px, translucent | +10% | Wide and soft, with an inner highlight. |

Use the identity control in the site header (or the sidebar footer on documentation pages) to
try them. The choice is kept in `localStorage` under `zk-identity`.

The built-in names are short on purpose: **Mist** is calm and soft, **Press** is editorial (ink on
paper, fine rules, serif titles), **Tide** is navy and coral, **Volt** is dense and dark with one electric
accent, **Maison** is a brand boutique (ivory, serif, airy), **Glass** is frosted translucent surfaces
over soft colour halos. `IdentityScript` also maps ids used before these names (`soft`,
`retro-square`, `studio`, `deep`, `luxe`, `gilt`) to the new ones and rewrites the stored value, so a
returning visitor keeps their choice. Pass `legacyIds` to map the ids of your own renamed identities.

Code blocks, tables, focused links and the documentation navbar and sidebar follow the same
tokens in every non-default identity: the default identity keeps the stock rendering.

## Add the switcher to your app

Import the stylesheet once. It already includes the identities and the motion tokens:

```css
@import "tailwindcss";
@import "@zedtech/zedkit-ui/styles.css";
@source "../node_modules/@zedtech/zedkit-ui/src";
```

Render `IdentityScript` in the root layout `<head>` so the stored identity is applied before the
first paint, then place `IdentitySwitcher` anywhere in the UI:

```tsx
import { IdentityScript, IdentitySwitcher } from "@zedtech/zedkit-ui";

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <IdentityScript />
      </head>
      <body>
        {children}
        <IdentitySwitcher />
      </body>
    </html>
  );
}
```

`IdentitySwitcher` is a labelled native `<select>` (accessible name "Identity", override with the
`label` prop). Pass `identities` to list your own entries. Light and dark keep working through your
existing theme provider.

## Create your own identity

Copy one of the blocks into your own stylesheet, rename the attribute value and change the
values. Declare it after the kit import. For the dark palette add a second block with the `.dark`
class.

```css
:root[data-identity="calm-blue"] {
  --background: 210 40% 98%;
  --foreground: 222 47% 11%;
  /* …every color token, see the list below… */
  --radius: 0.75rem;
  --radius-xl: 1rem;
  --zk-font-display: "Your Display Font", var(--zk-font-sans);
}

:root[data-identity="calm-blue"].dark {
  --background: 222 47% 8%;
  --foreground: 210 40% 98%;
  /* … */
}
```

Then register it so the switcher and the pre-paint script know about it:

```tsx
const mine = [
  { id: "mist", label: "Mist" },
  { id: "calm-blue", label: "Calm blue" },
];

<IdentityScript ids={mine.map((item) => item.id)} />
<IdentitySwitcher identities={mine} />
```

## Tokens to override

### Colors (HSL triplets, for light and for dark)

`--background`, `--foreground`, `--card`, `--card-foreground`, `--popover`, `--popover-foreground`,
`--primary`, `--primary-foreground`, `--secondary`, `--secondary-foreground`, `--muted`,
`--muted-foreground`, `--accent`, `--accent-foreground`, `--destructive`,
`--destructive-foreground`, `--success`, `--success-foreground`, `--warning`,
`--warning-foreground`, `--overlay`, `--border`, `--input`, `--ring`, and the `--sidebar*` set.

Keep text pairs at 4.5:1 or more (`foreground` on `background`, `card` and `muted`;
`muted-foreground` on `background`, `card`, `muted` and `secondary`; each `*-foreground` on its
surface). The built-in identities are checked with an automated accessibility test in both modes.

### Shape and depth

| Token | Controls |
| --- | --- |
| `--radius` | Base radius token read by the kit. |
| `--radius-xs` … `--radius-3xl` | The Tailwind radius scale (`rounded-md`, `rounded-xl`, …). Overriding the stock names also restyles the documentation framework, which reads the same variables. |
| `--zk-border-width` | Width of `border`, `border-t`, `border-b`, `border-l`, `border-r`, `border-x`, `border-y`. |
| `--zk-shadow-xs` … `--zk-shadow-xl`, `--zk-shadow-overlay` | The `shadow-*` scale. Use hard offsets for a flat look. |
| `--zk-shadow-color` | Color of hard shadows (HSL triplet). |

### Spacing and density

| Token | Controls |
| --- | --- |
| `--spacing` | Tailwind's base unit: every `p-*`, `gap-*`, `m-*` utility scales with it. |
| `--zk-density` | Multiplier on the kit's own padding and gap tokens (1 = stock). |
| `--zk-control-scale` | Multiplier on control heights (buttons, inputs). |

### Typography

| Token | Controls |
| --- | --- |
| `--zk-font-sans` | Body text and `font-sans`. |
| `--zk-font-display` | `h1` to `h4` and `font-display`. |
| `--zk-font-mono` | Code and `font-mono`. |
| `--zk-heading-weight`, `--zk-heading-tracking`, `--zk-heading-transform`, `--zk-heading-leading` | Heading weight, letter spacing, case and line height. |

Fonts are not bundled by the kit. Load them in your app (this site uses the self-hosted Fontsource
packages for Inter, Space Grotesk, Newsreader, Geist, Cormorant, Jost and JetBrains Mono, all under the SIL Open Font License 1.1) and name the
families in the tokens, with fallbacks. A font that no active identity names is never downloaded.

### Glass (translucent surfaces)

| Token | Controls |
| --- | --- |
| `--zk-glass-alpha` | Opacity of cards, popovers, code blocks, navbar and sidebar (1 is solid). |
| `--zk-glass-blur`, `--zk-glass-saturate`, `--zk-glass-filter` | The `backdrop-filter` behind those surfaces. |
| `--zk-glass-edge`, `--zk-glass-edge-alpha` | Colour and opacity of the hairline edge. |
| `--zk-glass-highlight` | Inner top highlight used in the shadow tokens. |

The `glass-surface` utility applies the same treatment to your own panels. Surfaces become solid
when the browser has no `backdrop-filter` or when the visitor asks for less transparency
(`prefers-reduced-transparency`), and the blur radius is smaller on phones. Cards, text and
controls keep a 4.5:1 contrast ratio in light and dark.

### Motion

| Token | Controls |
| --- | --- |
| `--zk-reveal-duration`, `--zk-reveal-distance`, `--zk-reveal-ease` | Entrance animations (`animate-fade-up`, `Reveal`, `Stagger`). |
| `--zk-stagger-step` | Delay between staggered items. |
| `--zk-lift-duration`, `--zk-lift-ease`, `--zk-lift-translate`, `--zk-lift-shadow` | `hover-lift` on cards. |
| `--zk-press-translate` | `hover-press` on buttons. |
| `--motion-fast`, `--motion-base`, `--motion-slow` | Dialog, drawer and menu transitions. |
| `--zk-btn-ease`, `--zk-btn-hover-translate`, `--zk-btn-hover-shadow`, `--zk-btn-press-shadow` | Hover and press on buttons. |
| `--zk-bg-pattern`, `--zk-bg-size`, `--zk-bg-repeat`, `--zk-bg-attach` | Page background texture or gradient. |
| `--zk-deco-ticker` | Whether the decorative ticker on the home page shows (`none` or `flex`). |

## Motion utilities and wrappers

Animations are classes and tokens, so they follow the identity:

- `animate-fade-up`, `animate-fade-in`, `animate-pop-in` with `stagger-1` to `stagger-12` for
  content above the fold (pure CSS, no flash).
- `hover-lift` for cards and `hover-press` for buttons.
- `Reveal` and `Stagger` for content below the fold: visible without JavaScript, revealed once
  when scrolled into view.

```tsx
import { Reveal, Stagger } from "@zedtech/zedkit-ui";

<Reveal>
  <SectionContent />
</Reveal>

<Stagger className="grid gap-4 md:grid-cols-3">
  <Card className="hover-lift">One</Card>
  <Card className="hover-lift">Two</Card>
  <Card className="hover-lift">Three</Card>
</Stagger>
```

Under `prefers-reduced-motion: reduce` every entrance and hover animation is turned off and
content is shown immediately.

## Preview every identity in the hero

`IdentityCycle` crossfades a whole hero through every identity (background, type, colours, cards,
visuals and buttons), then settles on the visitor's own (the stored choice, or the default). The
title, the promise and the main call to action keep the same words in every identity.

```tsx
import { IdentityCycle } from "@zedtech/zedkit-ui";

// Pass the whole hero as children. It is rendered once for real, and once more per identity while it plays.
<IdentityCycle backdrop>
  <Hero />
</IdentityCycle>
```

- It plays on every load of the page, in about three and a half seconds for six identities.
- The page never changes while it plays: `data-identity` on `<html>` is untouched, nothing is written
  to `localStorage`, and the switcher keeps showing the visitor's identity. Only the hero changes.
- Each identity is drawn by an `IdentityScope`, a wrapper that applies an identity to its subtree
  (`<IdentityScope identity="press">`). You can use it on its own for a preview or a comparison.
- `backdrop` paints each identity's own page background behind the scene, edge to edge of the window
  and a little beyond its top and bottom. Leave it off for a card.
- It waits for the page to finish loading, for the browser to be idle and for the identities' fonts, so
  it never delays the first paint. The real scene is always in the page flow, and the animated layers
  are absolutely positioned on top of it, so nothing moves.
- A click, a tap, a key press, a wheel or a touch stops it at once. Under `prefers-reduced-motion:
  reduce` it never plays.
- The animated layers are hidden from assistive technology and cannot take focus: keep the words
  identical in every identity, and the real links and buttons in the real scene.
  A scoped identity does not re-skin overlays that portal out of the scene (dialogs, popovers).

Pass `identities`, `stepMs`, `defaultIdentity`, `backdrop` or `enabled` to adapt it.

## Limits

- `rounded-full` is a fixed Tailwind value, so pills and switch thumbs stay round in every identity.
- A component that hard-codes a color, radius or shadow outside the token scales will not follow
  an identity; the kit components use tokens only.
- The shadcn registry theme item is generated from the mist palette; identities ship with the npm package.

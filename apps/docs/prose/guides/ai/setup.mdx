## Who this is for

You use a **coding agent** (Cursor, Muse, Claude Code, Codex, or similar) on a git repo (empty or already with team rules) and want one paste to hand the agent — no back-and-forth on how to start.

## Agent prompt (copy)

<AiSetupPrompt />

Agents should read the raw steps at [https://zedkit.app/ai/setup.md](https://zedkit.app/ai/setup.md) (plain markdown, no site chrome).

This guide targets `@zedtech/zedkit-ai` **1.2.0** (the current published version). Every command below pins it with `@1.2.0`; drop the suffix to float (not reproducible).

## What the agent will do

1. Add `@zedtech/zedkit-ai@1.2.0` if missing or not exactly at 1.2.0 (`pnpm add -D -w --save-exact` at a pnpm workspace root when `pnpm-workspace.yaml` exists).
2. Run `npx @zedtech/zedkit-ai@1.2.0 setup --provider cursor` (**`setup` preset by default**, adopt mode — keeps your files on collision; override with `--preset starter|setup|core|full` if needed). Use `--provider muse`, `claude`, `codex`, comma-separated names, or `all` to match your tool.
3. Run **`/zedkit-ai`** (or the `setup-ai` skill) — phases A–E (audit, **batched discovery interview** — answer or delegate, do not skip — build `product.md`, domain rules, personas, `design.md` when relevant, repo skills, score and learn), then verify and report. Muse does not scan `.agents/commands`; invoke the `zedkit-ai` skill by name. Paste **`zedkit-ai: set up this repo from what it contains`**.
4. Run `npx @zedtech/zedkit-ai@1.2.0 validate` until stdout is `ok`.

**Time:** about 15–45 minutes for a typical app repo once the agent starts (see the setup-ai skill intro).

## Single-repo vs workspace

| Situation | Where to paste the prompt |
| --- | --- |
| One git repository | That repo's root |
| Workspace with several checkouts | The workspace root first; `/zedkit-ai` runs workspace mode and proposes per-repo setup inside each child |

## Manual path (same result)

```sh
pnpm add -D --save-exact @zedtech/zedkit-ai@1.2.0   # workspace root: pnpm add -D -w --save-exact @zedtech/zedkit-ai@1.2.0
npx @zedtech/zedkit-ai@1.2.0 setup --provider cursor
```

Then **`/zedkit-ai`** in your agent, then:

```sh
npx @zedtech/zedkit-ai@1.2.0 validate
```

## Already on 1.1.x?

Re-run `npx @zedtech/zedkit-ai@1.2.0 setup` (adopt keeps your files; kit copies
land as `*.kit.md` / `zk-<name>`), then `/zedkit-ai`. Coming from 0.12? Follow
[Upgrading from 0.12](https://github.com/zedtech-fr/zedkit/blob/main/packages/ai/README.md#upgrading-from-012).
Opt-in `npx @zedtech/zedkit-ai@1.2.0 validate --setup` checks plan coverage, gate-log shape, and that the
setup went deep: `/zedkit-ai` (or the `setup-ai` skill) reads the code first with read-only subagents
(`npx @zedtech/zedkit-ai@1.2.0 scan` sizes them), writes domain rules and nested `AGENTS.md`
files from what they found, fills `.agents/tokenomics.md` (cheap models on
`check`/`build` at `trivial`/`standard`, the strong model on `sensitive`/`critical`),
and runs `npx @zedtech/zedkit-ai@1.2.0 sync`.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `validate` not `ok` | Run from repo root; fix each `path: message` line or re-run `setup` after resolving collisions. |
| Agent skips `/zedkit-ai` | Paste the prompt again; mechanical install alone is not done. |
| Muse shows no `/zedkit-ai` command | Paste **`zedkit-ai: set up this repo from what it contains`**. Muse does not scan `.agents/commands`; invoke the `zedkit-ai` skill by name. |
| Unknown provider | Use `cursor`, `claude`, `codex`, `muse`, `all`, or comma-separated names only. |

## Who this is for

You ship TypeScript apps (often React admin UIs, APIs, or content sites) and want small,
versioned packages instead of copying utilities from blog posts. You are fine installing
from npm and reading one catalog page when you know which need you have.

## When to use zedkit

Use zedkit when a documented need matches yours: the catalog lists imports, maturity,
and examples that stay aligned with the published package. Prefer your own code when
the need is highly specific to one product and will not be reused.

Reach for a **thin wrapper** around a mature npm library when zedkit does not list the
need yet (see the [golden rule](https://github.com/zedtech-fr/zedkit/blob/main/docs/golden-rule.md) in the repo).

Using shadcn/ui today? Read [zedkit and shadcn/ui](/docs/zedkit-and-shadcn) for what the UI
kit wraps, registry install vs npm, and when to stay on upstream shadcn.

## Prerequisites

- **Node.js** 22 or newer and **pnpm** 9 (same as the root README quickstart).
- **UI work:** React 19 and Tailwind CSS v4 in your app; follow the theme doc for tokens and the `.dark` class.
- **Agent setup:** a git repo on your machine; pick one provider flag for `zedkit-ai init` (`cursor`, `claude`, `codex`, `muse`, or `all`).

## Scenario

You inherit a monorepo with no agent instructions. You only need consistent skills for Cursor today.

1. Run Path A with `--provider cursor`.
2. Open the [AI setup catalog page](/docs/ai/set-up-ai-agent-instructions-skills-subagents-and-commands-in-a-repo) and run validate from the install tabs if you prefer copy from there.
3. Commit the files `init` created; re-run validate after you edit skills.

Next, add UI only when you start an admin screen — install `@zedtech/zedkit-ui` then, not on day one.

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `validate` fails after `init` | Run from the repo root; ensure `kit/` or `.agents/` copied; see [Check that skills, subagents, commands and provider copies are valid](/docs/ai/check-that-skills-subagents-commands-and-provider-copies-are-valid). |
| `init` refuses to overwrite | By design — remove or rename the conflicting file, or use `--dry-run` to preview. |
| UI components look unstyled | Theme doc not applied: Tailwind v4, kit CSS, and `.dark` on `html` when using dark mode. |
| Wrong package for the job | Search [the catalog index](https://zedkit.app/docs) by need; each page states **Avoid when**. |

## Who this is for

You ship TypeScript apps (React UIs, APIs, content sites, or scripts) and want small,
versioned packages **or** copied UI source in your repo — not one-off snippets from blog posts.
You are fine installing from npm or running the shadcn registry when a brick is published.

## When to use zedkit

Use zedkit when a documented need matches yours: the catalog lists imports, maturity,
and examples that stay aligned with the published package. Prefer your own code when
the need is highly specific to one product and will not be reused.

Reach for a **thin wrapper** around a mature npm library when zedkit does not list the
need yet (see the [golden rule](https://github.com/zedtech-fr/zedkit/blob/main/docs/golden-rule.md) in the repo).

Using shadcn/ui today? Read [zedkit and shadcn/ui](/docs/zedkit-and-shadcn) for what the UI
kit wraps, registry install vs npm, and when to stay on upstream shadcn.

## Install or copy

For **admin UI**, you can install the npm package or copy individual bricks with the shadcn CLI (your app needs a `components.json`). Composed bricks (drawer, confirm-dialog, …) depend on `@zedkit/*` siblings — register the namespace once, then add bricks:

```sh
{{snippet:registry-namespace.sh}}
```

The registry list grows over time; everything else stays npm-only.

Backend packages (`@zedtech/zedkit-core`, `@zedtech/zedkit-server`, `@zedtech/zedkit-nest`) are **npm-only** — install with your package manager; there is no shadcn registry copy path for them.

| Path | When to choose it | Command | What you get | Updates |
| --- | --- | --- | --- | --- |
| Install packages | Full kit, one import surface, theme tokens from the package | `{{snippet:ui-add.sh}}` | `@zedtech/zedkit-ui` (and peers you add) | Semver via your package manager |
| Copy via shadcn registry | Files in your repo, full control of one brick | `{{snippet:registry-add.sh}}` (or `npx shadcn@latest add zedtech-fr/zedkit/<brick>`) | Component source, its npm deps, and CSS variables in your globals | Manual — see [Updating copied files](/docs/zedkit-and-shadcn#updating-copied-files) on the shadcn guide |

Nothing in the catalog is labeled **stable** yet — see the [maturity legend](/docs/maturity-and-compatibility) before you ship. Theme tokens (colors, radius, focus rings, dark/light) ship with the npm package; copied bricks are plain editable files in your tree.

See [zedkit and shadcn/ui](/docs/zedkit-and-shadcn) for registry vs npm trade-offs.

## Prerequisites

- **Node.js** 22 or newer and **pnpm** 9 (same as the root README quickstart).
- **UI work:** React 19 and Tailwind CSS v4 in your app; follow the theme doc for tokens and the `.dark` class.
- **Agent setup:** a git repo on your machine; pick one provider flag for `zedkit-ai init` (`cursor`, `claude`, `codex`, `muse`, or `all`).

## Scenario — coding agents

You inherit a monorepo with no agent instructions. You only need consistent skills for Cursor today.

1. Run Path A with `--provider cursor`.
2. Open the [AI setup catalog page](/docs/ai/set-up-ai-agent-instructions-skills-subagents-and-commands-in-a-repo) and run validate from the install tabs if you prefer copy from there.
3. Commit the files `init` created; re-run validate after you edit skills.

Next, add UI only when you start an admin screen — install `@zedtech/zedkit-ui` then, not on day one.

## Scenario — backend

You ship a Node worker or API and want env validation before you handle traffic.

1. Run Path D and wire loadEnv from the server catalog page linked in that section.
2. For NestJS, run Path E and follow [Start a safe NestJS API](/docs/nest/start-a-safe-nestjs-api) (peer deps listed there).

## Scenario — SEO

You ship a Next.js site or content app and want sitemap, metadata, and structured data without ad hoc tags.

1. Install `@zedtech/zedkit-seo` with your package manager (npm-only). Use `@zedtech/zedkit-payload-seo` when Payload is your CMS.
2. Start from [Build localized page metadata](/docs/seo/build-localized-page-metadata), or follow [Add SEO to a Next.js app](/docs/add-seo-to-nextjs) for robots, sitemap, and JSON-LD in one pass.

## Scenario — UI

You add an internal admin to an existing React 19 app with Tailwind v4 and need consistent tokens before you ship screens.

1. Run Path B and wire theme CSS from [Theme an admin app](/docs/ui/theme-an-admin-app-dark-light-included) so buttons and forms are not unstyled.
2. Install the npm package for the full kit; copy a single brick from the registry only when you must edit source — [zedkit and shadcn/ui](/docs/zedkit-and-shadcn) compares both paths.
3. For sidebar, tables, and forms together, follow [Build an admin dashboard](/docs/build-an-admin-dashboard).

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| `validate` fails after `init` | Run from the repo root; ensure `kit/` or `.agents/` copied; see [Check that skills, subagents, commands and provider copies are valid](/docs/ai/check-that-skills-subagents-commands-and-provider-copies-are-valid). |
| `init` refuses to overwrite | By design — remove or rename the conflicting file, or use `--dry-run` to preview. |
| UI components look unstyled | Theme doc not applied: Tailwind v4, kit CSS, and `.dark` on `html` when using dark mode. |
| Boot fails on bad process.env | Standalone Node: [Path D](/docs/getting-started#quickstart) + [Fail fast on bad environment variables](/docs/server/fail-fast-on-bad-environment-variables). Nest: [Path E](/docs/getting-started#quickstart) + [Start a safe NestJS API](/docs/nest/start-a-safe-nestjs-api). |
| Wrong package for the job | Search [the catalog index](https://zedkit.app/docs) by need; each page states **Avoid when**. |

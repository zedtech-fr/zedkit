## What gets installed

One shared source plus a thin layer per provider. With
`preset: "core", providers: ["claude", "cursor"]`, `installKit` creates
(run it to see the reported action count):

```text
.agents/            # shared source: skills/, agents/, commands/, tokenomics.md
.claude/            # skills/commands link into .agents; agents generated by sync
.cursor/            # rules/project.mdc + skills link; agents generated by sync
```

Presets: `starter` (default), `setup` (starter plus domain, review lenses,
retro, and product/UI/copy subagents), `core` (planning and implement),
`full` (every skill). `init` also writes `AGENTS.md`/`CLAUDE.md` templates.
Supported providers: `claude`, `cursor`, `codex`, `muse`. `init` never
overwrites existing files. `zedkit-ai sync` writes each tool's agent files from
`.agents/agents` and `.agents/tokenomics.md`; `validate` reports drift, and
`zedkit-ai sync --check` prints `out of date, run: npx @zedtech/zedkit-ai sync`.

### Orchestrator

The `orchestrator` agent owns tasks that need several steps or lenses (plan,
review, implementation, audit, research, or a mix). It reads repo context and
the installed agent roster, decomposes work, dispatches self-contained briefs
(see `parallel-work`), aggregates evidence, and runs `verifier` before closing.
It never edits files. Limits by default: six subagents per wave, twelve total,
depth one, one retry per failed unit; no destructive git or deploy actions
without explicit approval. Invoke it via the `orchestrate` skill or `/orchestrate`.

## Personas

`persona-review` picks 2–4 personas per change from the repo's
`.agents/personas.md` (template: 8 rows — Stressed user, Lazy end client,
Integrating developer, Coding agent, Maintainer / operator, New
contributor, Security reviewer, Business owner) and requires evidence for
every Pass/Rough/Fail. Customize names and bars per project.

## Customize

- Add or remove an agent or skill: edit the `.md` file plus the `kit.json`
  lists, re-run `init`, then `validate` to catch drift.
- Repo rules live in `AGENTS.md` (the ladder section is appended, never
  overwritten).
- Upgrade from 0.12: re-run `npx @zedtech/zedkit-ai setup` (adopt on, preset
  `setup`). Colliding files stay yours; the kit copy lands as `*.kit.md` or
  `zk-<name>`. Then `/setup-ai` for discovery artifacts. Opt-in
  `/setup-ai` reads the code before it asks: read-only subagents (1–5 on a
  small repo, up to 20 on a big one; `zedkit-ai scan` sizes them) report the
  rules already in place, and the interview covers only the gaps. It writes
  domain rules, nested `AGENTS.md` files and `.agents/tokenomics.md`, then
  `zedkit-ai sync`.
  `zedkit-ai validate --setup` checks that the plan covers every git-changed
  path, that `.agents/setup-log/gates/*.log` start with `CMD:` and end
  with `EXIT:<code>`, and D4: a real model on `build.standard` and
  `decide.sensitive` in `.agents/tokenomics.md`, pointed at from `AGENTS.md`.
  Details: the package README `Upgrading from 0.12` section. The `verifier` agent plus the definition of done is the CI-side
  quality gate.

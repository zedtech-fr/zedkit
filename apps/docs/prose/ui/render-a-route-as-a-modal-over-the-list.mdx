## Drawer vs dialog vs page

| Content | Render as | Why |
|---|---|---|
| Filters, pickers, short forms on the current page | `Drawer` + `DrawerTrigger` (local state) | See [Slide in a drawer panel](/docs/ui/slide-in-a-drawer-panel) |
| Record detail from a list | `RouteModal` drawer (default) | Keeps list context; roomy; fullscreen on mobile |
| Destructive confirmation on a route | `RouteModal` `variant="dialog"` | Small, focused; Esc and backdrop dismiss |
| Destructive confirmation on local state | `ConfirmDialog` | No route — trigger plus callback |
| Multi-step flow, SEO, deep links | Full page | Overlays are for quick tasks, not journeys |

For a **local** slide-in (filters, quick edit) without a dedicated URL, use
`Drawer` with trigger state instead of an intercepting route.

## Next.js parallel and intercepting routes

Verified against `@zedtech/zedkit-ui` 0.4.0 and the docs workspace Next
version at writing time.

Open a list detail in an overlay without leaving the list: the URL stays
shareable (direct access renders the full page), closing returns to the
list with its query state intact. The kit owns `RouteModal` and
`closeRoute`; the app owns the route files and one shared detail view.

File tree for an `items` list with a detail overlay:

```text
app/items/
├── layout.tsx              # renders {children} + {modal}
├── page.tsx                # the list (links to /items/[id])
├── [id]/
│   └── page.tsx            # full detail page (direct access, refresh)
├── @modal/
│   ├── default.tsx         # null when no intercept is active
│   └── (.)[id]/
│       └── page.tsx        # intercept: same detail view in RouteModal
└── _detail-view.tsx        # shared view (both pages import this)
```

Layout with the modal slot:

```tsx
// app/items/layout.tsx
export default function ItemsLayout({
  children,
  modal,
}: {
  children: React.ReactNode;
  modal: React.ReactNode;
}) {
  return (
    <>
      {children}
      {modal}
    </>
  );
}
```

Intercept page (reuses the shared view so drawer and full page never drift):

```tsx no-preview="needs a Next.js intercepted navigation; the live RouteModal is the page preview above"
// app/items/@modal/(.)[id]/page.tsx
"use client";

import { use } from "react";
import { RouteModal, closeRoute } from "@zedtech/zedkit-ui";
import { useRouter } from "next/navigation";
import { DetailView } from "../../_detail-view";

export default function ItemModal({ params }: { params: Promise<{ id: string }> }) {
  const { id } = use(params);
  const router = useRouter();
  return (
    <RouteModal
      title="Item"
      onClose={() => closeRoute({ ...router, fallback: "/items" })}
    >
      <DetailView id={id} />
    </RouteModal>
  );
}
```

Default slot (no modal on direct load of the list or full page):

```tsx
// app/items/@modal/default.tsx
export default function ModalDefault() {
  return null;
}
```

Full-page detail (same `DetailView`):

```tsx no-preview="server route file that renders the shared detail view; the live result is the page preview above"
// app/items/[id]/page.tsx
import { DetailView } from "../_detail-view";

export default async function ItemPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  return <DetailView id={id} />;
}
```

## Closing and navigation

`closeRoute` prefers `router.back()` when the previous history entry is
same-document; otherwise it `replace`s the `fallback` path (bookmark,
external referrer, or single history entry):

```tsx
closeRoute({ back: router.back, replace: router.replace, fallback: "/items" });
```

`RouteModal` calls `onClose` only after the exit animation (or immediately
when `prefers-reduced-motion` is set). Wire `onClose` to `closeRoute`,
not raw `router.back`, so the panel finishes closing before navigation.

## Troubleshooting

- **Refresh shows the full page, not the drawer** — Expected: intercepts
  run only when navigating from the list. Direct `/items/[id]` loads the
  full-page route.
- **Closing drops list filters** — List state must live in the URL (search
  params) on `page.tsx`, not only in React state, so `back` restores it.
- **Modal and full page look different** — Import the same detail
  component in both `[id]/page.tsx` and `@modal/(.)[id]/page.tsx`.
- **`Cannot find module '../_detail-view'`** — From `@modal/(.)[id]/page.tsx` use
  `../../_detail-view` (the file sits on `items/`, not under `@modal/`). From
  `[id]/page.tsx` use `../_detail-view`.

# AI setup of this repo

This repo uses its own [`@zedtech/zedkit-ai`](../packages/ai/README.md) kit: the
skills and subagents in `packages/ai/kit/` are the single source of truth.

- `.agents/skills` (and `.claude/skills`, `.cursor/skills`) symlink into
  `packages/ai/kit/skills`.
- `.agents/agents`, `.cursor/agents` and `.claude/agents` are generated by
  `zedkit-ai sync` from the kit plus `tokenomics.md`. Muse needs a real
  directory (a kit dir-symlink empties its catalog).
- `CLAUDE.md` links to `AGENTS.md`.
- Instructions: root `AGENTS.md`, plus a nested `AGENTS.md` in each package,
  `apps/docs` and `deploy`. `.cursor/rules/*.mdc` only points at them.
- `personas.md`: the audiences `persona-review` picks from. PR bodies follow
  `.github/pull_request_template.md` (1–3 reviews chosen by risk; no fixed
  table, no CI prose check).
- Product / domain / tokenomics / design: `product.md`, `domain/*.md`,
  `tokenomics.md` (kind × stakes cells), `design.md`.
- `atlas.md`: the lookup read before any search (where things live, words,
  commands, why). One row per lesson, fixed in place, capped; `validate`
  checks its paths. Skill `rules-upkeep` says when to write it.

Edit skills and unmarked agent sources in `packages/ai/kit/`, then run
`npx @zedtech/zedkit-ai sync` and `pnpm exec turbo run test --filter=@zedtech/zedkit-ai`
(it builds the sibling packages first, validates the kit and checks skills
links plus generated agents). Licences and credits of vendored skills:
`packages/ai/kit/THIRD_PARTY_NOTICES.md`.

## Design loop

0. Unclear, or only questions? `/to-audit`. Have an audit? `/from-audit`.
1. `/plan` — research, spec, ladder, **assumptions table**. Never implements.
2. `/challenge` — stress-test the plan. **BLOCKING** if the assumptions table is missing.
3. `/implement` — the named unit, or the plan's first phase when none is named (`implementer` when the orchestrator fans out). Work branch; open the PR.
4. `/review` — punchlist (`reviewer`); apply via `improver`.
5. Close with `definition-of-done` and `rules-upkeep` (`Rules: none` when nothing to encode).

On every message, pick depth first (root `AGENTS.md`). A search or inventory is `audit`, not a grep-and-reply. Every numbered command hands to `orchestrate` (tokenomics + **build team**), except `/fix` and `/improve-from-review`, which stay inline. Plan, challenge and review: go deep, be strict, and be brutally honest.

## Commands

| Command | Does |
| --- | --- |
| `/plan` | Spec, tickets, ladder, assumptions. Never implements. |
| `/challenge` | Attack a plan. |
| `/implement` | Build from a challenged plan. |
| `/review` | Pin the diff, run lenses, one verdict. |
| `/orchestrate` | Coordinator: frame, dispatch, aggregate. Does not edit. |
| `/setup-ai` | Audit and tailor this setup. |
| `/improve-config` | Encode session learnings (skill `rules-upkeep`). |
| `/pr` | PR body. Does not open the PR (`implement` does, after definition-of-done). |
| `/handoff` | Hand off to the next builder. |
| `/audit` | Thorough audit: coverage map, evidence-backed findings. Investigates by default; fixes only when asked. |
| `/research` | Prior-art scout. |
| `/to-audit` | Topic audit from questions or an unclear plan. |
| `/from-audit` | Revalidate an audit against the current code; turn it into an actionable plan. |
| `/fix` | One defect, inline, with its check. Does not go through `orchestrate`. |
| `/improve-from-review` | Apply a review punchlist, then encode a reusable miss. |
| `/quick-wins` | `audit <scope>` finds small wins (read-only); `implement <findings or topic>` ships them. |

## Always-on vs globbed

Root `AGENTS.md` is always on (via `.cursor/rules/zedkit.mdc`): public hygiene, ladder, file budget, assumptions, living config. Nested `AGENTS.md` plus `.cursor/rules/nested.mdc` (`globs:` `**/`-prefixed, comma-separated) attach when those files are in play. `alwaysApply: true` only for the short root pointer.

## Public hygiene

This is a public repo. Never name a private project. Say "an upstream consumer". `scripts/check-no-private-refs.sh` and `scripts/check-tone.sh` fail the PR. A local consumer-setup dump at `the-good-example/` is gitignored on purpose.

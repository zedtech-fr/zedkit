# Docs framework spike

Context: shadcn-style docs site for a public TypeScript monorepo (pnpm,
Next.js-friendly, MDX, live React previews from workspace packages, light/dark).
Sources: official docs, GitHub repos, releases, npm only. Checked 2026-10-25.

## 2. Fumadocs

- MDX: first-class via `fumadocs-mdx` collections (`doc`/`meta`/`docs`), MDX
  compiler with default plugins. ([docs](https://www.fumadocs.dev/docs/mdx))
- Search + Cmd-K: built-in dialog, default hotkey Meta/Ctrl+K, Orama-powered
  with static-index option, swappable for Algolia. ([docs](https://www.fumadocs.dev/docs/ui/search))
- Dark mode: light/dark via `next-themes` in Root Provider, plus a shadcn
  CSS preset. ([docs](https://www.fumadocs.dev/docs/ui/theme))
- i18n: per-framework routing + Fumadocs config, `cli init --i18n`, `next-intl`
  suggested for the rest. ([docs](https://www.fumadocs.dev/docs/internationalization))
- Static/Vercel: server-first by default; static via Next.js `output: 'export'`
  (+ static Orama search). ([docs](https://www.fumadocs.dev/docs/deploying/static))
- Props tables: `<AutoTypeTable path name />`, TS Compiler API, RSC-only.
  ([docs](https://www.fumadocs.dev/docs/ui/components/auto-type-table),
  [npm 5.6.0](https://www.npmjs.com/package/fumadocs-typescript))
- Nav + previews: Page Tree auto-sidebar from files + `meta.json`, versioning
  built in; MDX runs in your Next.js app so workspace components import
  directly. ([docs](https://www.fumadocs.dev/docs/navigation))

## 3. Nextra

- MDX: file-based `page.mdx` routes, `_meta` nav files, `mdx-components.js`.
  ([docs](https://nextra.site/docs))
- Search + Cmd-K: Pagefind integration, enabled by default, needs a
  `postbuild` script. ([docs](https://nextra.site/docs/guide/search))
- Dark mode: theme switcher ships in `nextra-theme-docs`.
  ([source](https://github.com/shuding/nextra/blob/main/packages/nextra-theme-docs/src/components/theme-switch.tsx))
- i18n: Next.js locale routing, docs-theme only, locale switcher included.
  ([docs](https://nextra.site/docs/guide/i18n))
- Static/Vercel: documented `output: 'export'` + Pagefind postbuild to `out/`.
  ([docs](https://nextra.site/docs/guide/static-exports))
- Props tables: `<TSDoc>` properties table from `generateDefinition`,
  server-only, from `nextra/tsdoc` (underlying `@nextra/tsdoc` is a private
  monorepo package). ([docs](https://nextra.site/docs/built-ins/tsdoc))
- Nav + previews: `_meta`-driven nav; MDX in Next.js app imports workspace
  components directly; a `Playground` component exists.
  ([docs](https://nextra.site/docs/built-ins/playground))

## 4. Astro Starlight

- MDX: Markdown and MDX with zero config. ([docs](https://starlight.astro.build/guides/pages/))
- Search + Cmd-K: Pagefind built in, no configuration required.
  ([docs](https://starlight.astro.build/guides/site-search/))
- Dark mode: Dark/Light/Auto selector built into the header.
  ([docs](https://starlight.astro.build/getting-started/))
- i18n: best in class — `locales`/`defaultLocale` routing, fallback content,
  RTL, UI already translated incl. French. ([docs](https://starlight.astro.build/guides/i18n/))
- Static/Vercel: static by default, zero-config Vercel deploy.
  ([docs](https://docs.astro.build/en/guides/deploy/vercel/))
- Props tables: none built in (official set is Cards/Tabs/Steps/etc.).
  ([docs](https://starlight.astro.build/components/using-components/))
- Nav + previews: directory-autogenerated sidebar + frontmatter overrides;
  MDX can import components, but React previews need Astro's React
  integration (islands), so workspace React components are second-class.
  ([sidebar](https://starlight.astro.build/guides/sidebar/),
  [components](https://starlight.astro.build/components/using-components/),
  [React](https://docs.astro.build/en/guides/framework-components/))

## 5. Velite-based custom site

Velite is a content layer, not a docs theme: MDX/Markdown/YAML/JSON to
type-safe data via Zod schemas ([readme](https://github.com/zce/velite),
[quick-start](https://velite.js.org/guide/quick-start), MDX + Next.js guides
in its sidebar). Search, dark mode, i18n, nav, previews, and props tables are
all DIY on top of your own Next.js app — maximum control, maximum build cost.

## 6. PR previews on a private repo

Framework-independent: Vercel gives every branch a Preview environment
([docs](https://vercel.com/docs/deployments/environments)); all four options
deploy to Vercel the same way regardless of repo visibility.

## Recommendation

Choose Fumadocs: it is the only option that is simultaneously under active
maintenance (release days ago, ~2 open issues), Next.js-native (workspace
React components import directly into MDX for live previews with light/dark
via `next-themes`), shadcn-aligned (dedicated CSS preset, and shadcn's own
docs now run on it), and complete out of the box (Cmd-K Orama search with a
static-export path, `meta.json`-generated nav with versioning, `fr`/`en`
i18n support, and compiler-accurate `<AutoTypeTable>` props tables) —
whereas Nextra is stale, Starlight demotes React previews to islands, and
Velite rebuilds the entire theme by hand.
